# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest  | Yes       |

Only the latest release receives security patches.

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

To report a vulnerability, use [GitHub's private vulnerability reporting](https://github.com/laplacef/webgoat-broken-access-control/security/advisories/new). You can expect an initial response within 72 hours.

Please include:
- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact assessment

## Scope

The following are considered security issues:
- Dependency vulnerabilities in the site build toolchain
- Malicious content reachable through embedded links, assets, or references

## Out of Scope

The following are **not** security issues:
- Vulnerabilities in WebGoat itself. WebGoat is deliberately vulnerable software and is the subject of study here; report those upstream
- Exploit techniques described in the case studies, which document published vulnerability classes
- Accuracy or completeness of a case study's analysis
